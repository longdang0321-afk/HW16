# 과제 16: 순차 탐색과 이진 탐색의 성능 비교

> **핵심 결과 요약**
> - 퀵 정렬의 최초 비교 횟수: **605,388회** (한 번만 발생)
> - 정렬 비용을 포함한 이진 탐색이 순차 탐색보다 처음 유리해지는 시점: **K = 19**
> - K = 1,000일 때 총 비교 횟수: 순차 탐색 32,033,000회, 퀵 정렬 + 이진 탐색 624,994회 (약 **98.05% 감소**)

---

## 1. 프로그램 설명

### 1.1 동작

1. CSV 파일에서 학생 **32,033명**의 학번, 이름, 성별, 국어·영어·수학 점수를 읽어 배열에 저장한다. 총점은 세 과목 점수의 합으로 계산한다.
2. `Enter student name:` 안내에 따라 검색할 이름을 입력한다. 동명이인이 있으면 일치하는 학생을 **모두** 출력한다. 출력 항목은 학번, 이름, 과목별 점수, 총점이다.
3. 입력한 이름의 검색 결과를 순차 탐색과 이진 탐색으로 각각 출력한다.
4. 이어서 검색 횟수 K에 따른 두 방법의 총 비교 횟수를 자동으로 측정하여 표로 출력한다.

```text
Enter student name: Liam
```

### 1.2 구현 방식

| 방법 | 사용하는 배열 | 탐색 방식 |
|---|---|---|
| 순차 탐색 | CSV에서 읽은 **원본 배열** (정렬하지 않음) | 처음부터 끝까지 이름을 차례로 비교 |
| 퀵 정렬 + 이진 탐색 | 원본을 **복사**한 배열 (이름 오름차순으로 퀵 정렬) | 정렬된 배열에서 이진 탐색 |

두 방법 모두 이름 비교에 `strcmp()`를 사용한다. 비교 연산은 한 번 호출할 때마다 비교 횟수를 1 증가시킨다.

직접 입력한 이름을 검색할 때의 비교 횟수는 초기화하여 자동 실험 결과에 포함하지 않는다. 퀵 정렬 비용은 자동 실험의 각 누적 결과에 **한 번만** 포함한다.

---

## 2. 검색 결과 확인

`Liam`을 입력한 결과, 두 방법 모두 다음 5명의 학생을 찾았다.

| 학번 | 이름 | 국어 | 영어 | 수학 | 총점 |
|---|---|---:|---:|---:|---:|
| 100001 | Liam | 89 | 16 | 66 | 171 |
| 100743 | Liam | 67 | 50 | 8 | 125 |
| 102534 | Liam | 84 | 54 | 78 | 216 |
| 103283 | Liam | 59 | 61 | 90 | 210 |
| 109860 | Liam | 72 | 83 | 62 | 217 |

두 방법의 출력 **순서는 달랐지만** 학생과 점수는 모두 일치하였다. 퀵 정렬은 안정 정렬이 아니어서 같은 이름을 가진 학생들의 상대적인 순서가 바뀔 수 있기 때문이다. 이 과제에서는 동명이인의 정보를 모두 찾는 것이 중요하며, 같은 이름 안에서 학번순 정렬을 요구하지는 않는다.

---

## 3. K의 설정과 실험 방법

### 3.1 K의 정의

K는 **검색 횟수**이다. 한 번 검색하여 동명이인 5명을 찾더라도 K는 1이다.

### 3.2 K의 범위와 그 이유

| 항목 | 값 | 이유 |
|---|---|---|
| 시작값 | 1 | 검색이 매우 적을 때 초기 정렬 비용이 미치는 영향을 확인하기 위해 |
| 증가 폭 | 1 | 두 방법의 비교 횟수가 역전되는 시점을 정확히 찾기 위해 |
| 최댓값 | 1,000 | 검색이 많아졌을 때의 차이를 충분히 확인하기 위해 |

K = 1부터 1,000까지 모두 측정하되, 화면에는 K = 1~30, 50, 그리고 이후 100 간격의 주요 결과를 표시하였다. 표의 값은 해당 K까지의 **누적** 비교 횟수이다.

### 3.3 검색 이름 목록

- k번째 검색에서 k가 5의 배수이면 존재하지 않는 이름 `__NO_SUCH_STUDENT__`를 검색한다.
- 그 외에는 원본 배열의 `(k - 1) % n` 위치에 있는 학생의 이름을 검색한다.
- 따라서 총 1,000번 중 **800번은 존재하는 이름**, **200번은 존재하지 않는 이름**을 검색한다.
- 같은 검색에서 두 방법에 **동일한 이름**을 전달한다.
- K가 증가하면 기존 검색 목록에 새로운 검색 하나를 추가한다.

---

## 4. 비교 횟수 측정 기준

```text
순차 탐색 총 비교 횟수          = K번의 순차 탐색 비교 횟수 합
퀵 정렬 + 이진 탐색 총 비교 횟수 = 최초 퀵 정렬 비교 횟수 + K번의 이진 탐색 비교 횟수 합
```

- **퀵 정렬의 최초 비교 횟수는 605,388회**이다. 정렬은 한 번만 수행하고, 각 K에서 이 비용에 이진 탐색의 누적 비교 횟수를 더하였다.
- CSV 읽기, 배열 복사, 총점 계산, 출력은 비교 횟수에 포함하지 않았다.
- **순차 탐색**은 동명이인을 모두 찾기 위해 배열 끝까지 확인한다. 따라서 한 번 검색할 때 항상 32,033회, K번 검색할 때는 정확히 `32,033 × K`회 비교한다.
- **이진 탐색**은 검색 이름 이상인 첫 위치를 찾은 후, 그 위치부터 같은 이름의 학생을 모두 확인한다. 이진 탐색 중의 비교뿐 아니라 동명이인을 확인하는 비교와 마지막 불일치 비교도 포함하였다.

## 6. 결과 분석

### 6.1 K가 작을 때: 순차 탐색이 유리하다

K = 1에서 순차 탐색은 32,033회만 비교하지만, 퀵 정렬 + 이진 탐색은 605,409회를 비교한다. 이 중 실제 이진 탐색의 비교는 `605,409 - 605,388 = 21회`이다.

이진 탐색 자체는 매우 적게 비교하지만, 최초 정렬 비용이 순차 탐색 한 번의 약 18.9배(`605,388 ÷ 32,033`)이므로 검색 횟수가 적을 때는 순차 탐색이 유리하다.

### 6.2 역전되는 시점과 원인

| K | 순차 탐색 | 퀵 정렬 + 이진 탐색 | 차이 |
|---:|---:|---:|---|
| 18 | 576,594 | 605,752 | 순차 탐색이 29,158회 적음 |
| 19 | 608,627 | 605,773 | 퀵 정렬 + 이진 탐색이 2,854회 적음 |

따라서 **역전 구간은 K = 18과 K = 19 사이**이며, K = 19번 검색했을 때부터 정렬 후 이진 탐색 방식이 유리해지기 시작한다.

**원인.** 두 방법의 차이는 "한 번 내는 정렬 비용"과 "검색할 때마다 절약하는 비용"의 경쟁으로 설명할 수 있다.

- 순차 탐색은 검색 한 번에 32,033회, 정렬 후 이진 탐색은 검색 한 번에 약 20회를 비교한다. 따라서 검색 한 번마다 **약 32,013회**를 절약한다.
- 이 절약량이 초기 정렬 비용 605,388회를 넘으려면 `605,388 ÷ 32,013 ≈ 18.9`번의 검색이 필요하다.
- 검색 횟수는 정수이므로 처음 역전되는 K는 **19**이다.

즉 역전 시점은 대략 `정렬 비용 ÷ (검색당 절약 비교 횟수)`로 결정된다. 데이터 크기 N, 정렬 구현, 동명이인 수가 바뀌면 이 값도 달라진다.

### 6.3 K가 커질 때: 정렬 비용의 부담이 줄어든다

순차 탐색은 검색을 추가할 때마다 32,033회씩 **일정하게** 증가한다. 반면 정렬된 배열에서는 검색당 비교 횟수가 약 20회로 적으므로, 퀵 정렬 + 이진 탐색의 총 비교 횟수는 천천히 증가한다.

K = 1,000에서 이진 탐색만의 누적 비교 횟수는 `624,994 - 605,388 = 19,606회`이고, 검색당 평균은 19.606회이다. 초기 정렬 비용은 한 번만 발생하므로 K가 증가할수록 **검색당 평균 정렬 부담은 줄어든다**.

정렬 비용까지 포함한 K = 1,000의 총 비교 횟수는 순차 탐색 32,033,000회, 퀵 정렬 + 이진 탐색 624,994회이다. 후자는 전자보다 약 98.05% 적다. 다만 이는 **이름 비교 횟수**의 차이이며, 실행 시간도 같은 비율로 감소한다는 의미는 아니다.

### 6.4 검색당 비교 횟수가 약 20회인 이유

N = 32,033일 때 `log₂ N ≈ 15`이다. 측정된 검색당 평균 약 20회는 이진 탐색 자체의 비교에 **동명이인을 확인하는 비교와 마지막 불일치 비교**가 더해진 값이다. 동명이인이 없는 이름이라면 이 추가분은 작지만, 동명이인이 많을수록 늘어난다.

퀵 정렬의 605,388회는 `N log₂ N ≈ 479,447`의 약 1.26배로, 퀵 정렬의 평균 시간 복잡도 `O(N log N)`과 같은 규모이다.

---

## 7. 두 방법의 장단점

| 방법 | 장점 | 단점 |
|---|---|---|
| 순차 탐색 | 구현이 간단하다. 정렬 없이 바로 검색할 수 있다. 검색 횟수가 적을 때(K ≤ 18) 유리하다. | 동명이인을 모두 찾으려면 매번 전체 배열을 확인해야 하므로 반복 검색의 비용이 크다. |
| 퀵 정렬 + 이진 탐색 | 정렬된 데이터를 반복 검색할 때 비교 횟수가 매우 적다. | 초기 정렬 비용과 복사 배열(추가 메모리)이 필요하다. 데이터가 변경되면 정렬 상태도 관리해야 한다. |

- 이진 탐색도 동명이인이 m명이면 해당 학생을 모두 확인해야 하므로 검색 비용은 `O(log N + m)`이다.
- 퀵 정렬은 평균 `O(N log N)`이지만 최악의 경우 `O(N²)`이 될 수 있다.

---

## 8. 결론

- 검색 횟수가 적으면(K ≤ 18) 정렬 비용을 회수하지 못하므로 **순차 탐색**이 유리하다.
- K = 19부터는 정렬 비용을 포함하더라도 **퀵 정렬 + 이진 탐색**의 총 비교 횟수가 더 적고, K가 커질수록 격차가 커진다.
- 다만 이 역전 시점(K = 19)은 이번 데이터(N = 32,033), 퀵 정렬 구현, 검색 목록에서 얻은 결과이며, 모든 데이터에서 항상 19번에 역전되는 것은 아니다.
